## Project Overview

GitSetup is a macOS-only Bash CLI tool that automates Git, SSH, and GPG environment configuration. It manages multiple Git identities via a single `.env` file, generating SSH keys, global gitconfig, and post-checkout hooks that switch user identity based on remote URL.

## Commands

```bash
# Run functional tests
./tests/test_setup.sh

# Run the tool (requires .env)
./bin/git-setup

# Dry-run (no changes)
./bin/git-setup --dry-run

# Non-interactive
./bin/git-setup --yes

# Cleanup all generated configs
./bin/git-setup --clean
```

## Architecture

Entry point: `bin/git-setup` — guards macOS-only, parses flags, sources all libs, runs `main()`.

Libraries in `lib/` are sourced (not subshelled) and share scope:

- `config.sh` — loads `.env`, validates required vars, provides `config_for_each_profile` iterator
- `ssh_manager.sh` — generates Ed25519 keys per profile, updates `~/.ssh/config` using marker blocks
- `git_manager.sh` — applies gitconfig/gitignore templates, generates post-checkout/post-commit/post-merge hooks for identity switching, optional commit-msg hook for Conventional Commits
- `gpg_manager.sh` — finds/generates GPG keys per email, configures git signing
- `cleaner.sh` — reverse of setup: removes keys, configs, hooks
- `logger.sh` — colored output (`log_info`, `log_success`, `log_warning`, `log_error`)
- `utils.sh` — `utils_execute` (dry-run aware), `utils_confirm`, `utils_backup_file`, `utils_update_block_from_stdin` (marker-based file block management)

Key pattern: `config_for_each_profile <callback>` iterates `GIT_PROFILES` (comma-separated `host:email` pairs) and calls the callback with `(host, email)`. Multiple modules use this pattern with internal `_module_process_profile` callbacks.

## CI/CD

- GitHub Actions on `macos-latest`
- semantic-release on `main` branch (configured in `.releaserc.json`)
- Commits must follow Conventional Commits format
- PR titles validated via `.github/workflows/pr-title.yml`

## Repo Conventions

- All shell scripts use `#!/bin/bash`.
- Every `.sh` file starts with the repository header block (File, Description, Author, License, Copyright).
- Destructive operations go through `utils_execute` for dry-run support
- SSH config uses `# ==================== GITSETUP START/END ====================` markers
- Hook scripts contain `# Hook generated by GitSetup` for detection
- Node.js (`package.json`, `node_modules/`) exists solely for semantic-release tooling — not part of the app
